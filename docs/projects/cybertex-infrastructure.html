CyberTex infrastructure & cloud capstone

Server lab direction and team cloud architecture work spanning virtualization, directory services, recovery evidence, and technical handover.

The server and cloud work required more than installing software. A useful team environment needs clear roles, understandable network services, recoverable changes, operational evidence, and a handover that another person can follow.

My contribution

I led direction and evidence organization in the server work and served as Design & Standards / Cloud Architect for the team AWS capstone. I worked through team responsibilities, architectural decisions, acceptance criteria, documentation, and AI-assisted execution. The records explicitly distinguish my direction from Codex execution and teammate work.

Server lab accomplishments

  • Configured and persisted isolated Proxmox network bridges.
  • Supported Windows Server promotion and Active Directory/DNS implementation.
  • Collected directory, DNS, and SYSVOL health evidence.
  • Documented DHCP configuration, authorization, and a real Ubuntu client lease/options readback.
  • Preserved failed changes and successful rollback evidence.
  • Produced team presentations, remote-access procedures, and build documentation.

The work involved Proxmox VE, Linux, Windows Server, AD DS, DNS/DHCP, virtualization, storage, and Tailscale planning. Infrastructure identifiers and original network evidence remain private.

Cloud capstone deliverables

The architect-owned package includes architecture and naming standards, cost/storage decisions, serverless API contracts, least-privilege boundaries, a responsibility matrix, decision records, deployment/runbook criteria, and an evidence checklist.

The project repository contains CloudFormation templates and final-write-up material. October records include actual AWS baseline readbacks for network and budget objects. Those observations are bounded infrastructure evidence, rather than proof that the whole application was deployed.

Evidence and status

The reviewed records support completed architecture/documentation deliverables and real lab observations. Final live API integration, final team submission/handover, off-array recovery, and remaining network acceptance are separate dependencies. A prepared hardening handoff is not a deployed security control.

The course certificates document completion records. Coursework involved AI assistance, and the portfolio does not treat those records as vendor exam credentials or an independent skills assessment.

Skills demonstrated: architecture, network/service reasoning, least privilege, cloud cost planning, team coordination, operational evidence, change recovery, technical handover.
